# 目的

给一个**守卫/拒绝分支**（返回 UNARMABLE/BUSY/INVALID/FULL 之类）补回归断言，且避免三条常见失败：测了却测不到（前置状态不成立）、测了但不可能失败（无牙口）、断言块之间状态串味。

# 步骤

1. **先确认真实前置状态，不要凭直觉判"难构造"。** 追发出点而不是猜：
   - 解析器无条件发出的指令：LuaJIT 里 `BC_FORI` 来自 `lj_parse.c:2862`（每个数值 for），`BC_ITERN/ISNEXT` 来自泛型 for。
   - 运行期被 JIT 改写的：`lj_trace.c:517` 在回边起 trace 时把 `FORI` 一起 patch 成 `JFORI`；`PROTO_NOJIT`（`jit.off(f, true)`）的冷/热切换由 `trace_start()` 的 NOJIT 分支把 `FORL→IFORL`、`FUNCF→IFUNCF` 懒 patch。
   - 因此"包装过/未包装过/被 JIT 排除"三种状态的槽都能用普通 Lua + `jit.opt.start('hotloop=1')` 造出来。
2. **断言前置状态，再断言守卫。** 用可观测 API 读出当前槽真实是什么（LuaJIT：`jit.util.funcbc` + `bcnames`；注意 `lua_tointeger` 会把高位为负的指令变成负数，比较前 `& 0xff`）。前置断言失败要能立刻区分"守卫没拒绝"和"根本测的是另一个状态"。
3. **逐条牙口验证。** 临时把守卫表里**一个**条目删掉，重建，跑：必须只有对应的那一条断言红。逐条目做，不要一次删多个。还原后校验源码 diff 为空（必要时比对 blob hash）。
4. **断言块之间重置共享记录结构。** 复用同一个 `memset` 掉的记录时，上一个子用例残留的标志（如 `stop_after`）会让新断言走错分支并级联出多红——牙口验证时这点尤其致命，因为它把"测试有问题"伪装成"守卫有问题"。
5. **覆盖矩阵要写出来。** 数清守卫表条目总数与已固定数，列出未固定项各自怎么构造；别把"未测"说成"不可测"，除非能指出确切的不可达理由（例如某变体没有任何发出点）。

# 反例（真实踩过的）

- 把 `BC_FORI` 断言说成"需要人造原型、成本高于收益"——实际未运行过的数值 for 原型里就是 `FORI`。
- 把 x64 `r12` 覆写说成"C 侧不可观测 ⇒ 无法回归测试"——实际上 Win64 ABI 汇编外壳（保存→播种子→`lua_pcall`→比对，32 字节影子空间 + 16 对齐）能看到；若目标库自己 `push/pop r12` 掩盖了写坏值，就在**调用内部**用 naked C 函数做前后采样（只采该后端不当参数使用的寄存器，如 r12–r15）。
