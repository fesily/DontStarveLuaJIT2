# FastHook world generation comparison: October 15, 2026

With the current FastHook runtime, the local LuaJIT VM takes 25.71% less map
wall time and 28.68% less map process CPU time than the embedded game VM in
three paired measurements. The previous large ordinary Gum interception
hotspot is absent from two additional diagnostic pairs.

Here `jit` names the LuaJIT VM selector. The profile preserves the game's
default JIT policy, and every LuaJIT map entry records `jit=false`. These
results measure the LuaJIT interpreter with compatibility support, rather
than compiled traces.

## Timing comparison

Seconds below are medians of three measured runs. Changes use geometric
means of candidate/baseline ratios paired by round; they need not equal
the ratio of the medians.

| Metric | Embedded game | LuaJIT, compiler off | Paired ratio | Time change |
| --- | ---: | ---: | ---: | ---: |
| Map wall time | 2.808549 | 2.062658 | 0.742895 | -25.71% |
| Map process CPU time | 3.187500 | 2.187500 | 0.713229 | -28.68% |
| Server launch to ready | 23.621598 | 21.844258 | 0.922488 | -7.75% |
| Test including teardown | 27.244993 | 24.832321 | 0.906409 | -9.36% |

| Measured round | Order | Game map wall time | LuaJIT map wall time |
| --- | --- | ---: | ---: |
| 1 | jit, game | 2.857685 | 2.037103 |
| 2 | game, jit | 2.808549 | 2.062658 |
| 3 | jit, game | 2.773677 | 2.172175 |

Game map wall range: 2.773677-2.857685 s. LuaJIT range:
2.037103-2.172175 s. Every paired LuaJIT map time is lower.
The first game warmup has a 53.406962 s server startup, versus
22.019625 s for the LuaJIT warmup; both warmups are excluded by policy.
Measured server startups range from 23.552328-23.700608 s for game
and 21.571044-21.967267 s for LuaJIT.

The map interval starts at entry to `forest_map.Generate` and ends at its
return, observed externally at the probe's stdout markers. It includes
native generator calls. It excludes prior module loading, entity injection
after Generate, and save serialization. Wall time uses the parent's
`perf_counter`; CPU time uses `GetProcessTimes` at the same observations
and covers the whole process. Both boundaries include stdout delivery
latency. Server startup runs from immediately before server `Popen` to
the session-ready log.

The game baseline has 345 snapshots, primarily in the game executable
(81.74%) and its CRTs. No sampler errors are recorded.

The two LuaJIT runs contain 768 Lua samples: C 72.27%, interpreter 26.95%,
and GC 0.78%. The leading C stacks are under `generate` and
`on_region_added_fn` / `AddRegionsToMainland`. In the installed
`map/forest_map.lua`, the corresponding region setup invokes the native
WorldSim Voronoi passes. C VM state alone is not evidence of hook overhead;
the external module observations no longer reproduce the Gum hotspot.

Outermost uncached require intervals average 0.131785 s for game and
0.104834 s for LuaJIT. These include file loading, parsing and module
execution, including nested loads, within Generate. They are not
parser-only measurements and exclude modules loaded before Generate.

The [October 14 investigation](2026-10-14-hotspots.md) had 46.88% of
LuaJIT snapshots outside loaded modules and 25.78% in frida-gum.dll in
its final pair; Square fill took 3.646376 s. Here neither category is
observed and Square fill takes 0.405721-0.455270 s. The older normal
JIT-off map median was 7.666627 s; the current median is 2.062658 s.
These are separate batches, with different game-baseline times, rather
than a contemporaneous paired comparison of the old and new runtimes.
The result supports removal of the dominant ordinary interception cost;
it does not measure the remaining cost of individual compatibility features.

Native observations use SuspendThread/GetThreadContext/ResumeThread
snapshots of WorldSim, not CPU samples or native call stacks. The
requested interval is 5 ms and observed median spacing is about 15.6 ms.
Suspension calls total 0.024498 s across both game runs and 0.019080 s
across both LuaJIT runs; other sampling perturbations are not quantified.
Zero Gum snapshots does not establish zero overhead for the direct relay.

## Reproduction and artifacts

```powershell
python -u tests/performance/run.py --profile worldgen `
  --worldgen-jit default --warmup 1 --repeat 3 `
  --vm jit=builds/game-performance-vm-release/luajit/lua51DS.dll `
  --injector builds/game-performance-runtime-release/src/DontStarveInjector/Release/Injector.dll `
  --output builds/game-performance-20261015-fast-hook-comparison

python -u tests/performance/run.py --profile worldgen `
  --worldgen-jit default --sample-lua --sample-native --warmup 0 --repeat 2 `
  --vm jit=builds/game-performance-vm-release/luajit/lua51DS.dll `
  --injector builds/game-performance-runtime-release/src/DontStarveInjector/Release/Injector.dll `
  --output builds/game-performance-20261015-fast-hook-hotspots

python tests/performance/analyze.py `
  builds/game-performance-20261015-fast-hook-hotspots --disassemble
```

The two output directories contain results.json, results.csv and per-run
logs. The diagnostic directory also contains observations, raw native
captures and hotspots.json. Full Release build evidence and runtime
module hashes are embedded in results metadata.

Warmups only reduce cache/first-launch effects: each following sample has
a new VM. Fixed seed does not guarantee identical maps across different
VM RNG and table iteration behavior. These descriptive measurements cover
one seed and world size, and do not establish general game FPS or simulation
performance. The game baseline contains the injector; it is not an
unmodified installation.
